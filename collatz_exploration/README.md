# Collatz Conjecture: Representation-Dependent Structure

A proof-of-concept exploration of how **representation changes what becomes computationally visible** in an open conjecture.

## Hypothesis

The same mathematical problem, expressed in different representations, reveals different structural patterns and suggests different proof strategies. Applied to Collatz:

> **Does representation govern which aspects of Collatz become visible?**

## Four Representations

### 1. **Direct Representation**
- **What you do:** Iterate $n \to 3n+1$ or $n \to n/2$
- **What's visible:** Trajectory length to reach 1
- **Structure revealed:** None (black box)
- **Algorithmic approach:** Brute-force verification

### 2. **Binary Representation**
- **What you do:** Work with bit patterns, trailing zeros (power-of-2 divisibility)
- **What's visible:** Binary digit patterns, power-of-2 chains
- **Structure revealed:** Divisibility structure in low bits
- **Algorithmic approach:** Bit-level heuristics, shift optimizations

### 3. **Modular Representation**
- **What you do:** Analyze constraints modulo small primes (2, 3, etc.)
- **What's visible:** Algebraic cycles, modular obstructions
- **Structure revealed:** Which residue classes form cycles/chains
- **Algorithmic approach:** Eliminate candidates via modular constraints (like SAT/SMT)

### 4. **Graph Representation**
- **What you do:** Build inverse tree: which $n$ lead to $m$? (Backward from 1)
- **What's visible:** Tree topology, reachability depth, branching structure
- **Structure revealed:** Global graph structure encoding all Collatz paths
- **Algorithmic approach:** BFS/DFS on reachability tree

## Key Files

- `collatz_representations.py` — Main experiment; runs all four representations
- `interpret_results.py` — Visualization and interpretation script
- `collatz_results.json` — Output data (generated by first script)

## Quick Start

```bash
# Run the analysis (compares all four representations up to n=500)
python collatz_representations.py 500

# Interpret results and see what each representation reveals
python interpret_results.py collatz_results.json
```

## Expected Output

A detailed breakdown of:
- **Mean trajectory length** (direct: ~60-100 steps typical)
- **Binary patterns found** (how many unique bit signatures?)
- **Modular cycles** (which residue classes form chains?)
- **Graph depth** (maximum distance from 1 in inverse tree?)

## Connection to Main Paper

This exploration tests whether the principle from `paper_draft.md`:

> **"Representation governs search reachability under bounded budgets"**

applies beyond hypergeometric certificates to open conjectures. In Collatz:

- Each representation acts as a *different search space*
- Some reveal structure (modular, graph) better than others (direct)
- An algorithmic search strategy that works in one representation may fail in another

## Limitations

- **No proof** (obviously — Collatz is open)
- **No verification** that any representation uniquely solves it
- **Small search budget** (typical $n < 10^6$ for computational tractability)
- **Exploratory only** — demonstrates the principle, doesn't advance Collatz itself

## What This Demonstrates

✓ Same problem, four different representations  
✓ Each reveals different structural patterns  
✓ Different algorithmic approaches become plausible in each  
✓ **Representation controls visibility**, not just efficiency
